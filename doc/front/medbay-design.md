- shadcn/ui (new-york) in `frontend/components/ui/` + `lib/utils.ts cn()`; Radix primitives via `components.json`. Legacy `.panel`/`.callout`/`.modal-card` re-defined with the same surface treatment.
- Icons: `components/icons/medbay.tsx` = thin **lucide-react** wrappers (same MEDBAY export names + `size` API). The three `Logo*Icon` wordmarks are **static SVG assets** in `frontend/public/brand/medbay-{station,ship,ground}.svg` — generated by `frontend/scripts/gen-logo-assets.py` (fontTools + bundled `@fontsource/unbounded` woff files at the supplied design SVGs' tspan coordinates; location accent + white "DB" as literal hex fills). They render as plain `<img>` (`size` = height, width auto) so nothing depends on webfonts, CSS vars or `currentColor`; each asset can be opened directly at `/brand/<file>.svg` for debugging.
- Location theme: `useLocationTheme` + `data/mission.ts` (`station` / `spacecraft` / `mars` ids, subtitled STATION/SHIP/GROUND CARE). Theme changes animate via a 240ms global token transition; page content enters via `.medbay-enter` keyed on `usePathname` (AppShell).
- Header: `MedbayHeader` angled plate + `MedbayLogo`, headline slot via `useHeadline` store, subject-health LED (pulses on critical), ghost icon buttons (evidence/DB/menu/LLM), "I'M A MEDICAL PROFESSIONAL" view pill. All headline/controls sit in a sub-row padded by `BAND_H` (36px) so the accent band line never crosses text or buttons; the logo stays vertically centred inside the full-height plate.

## Visual AI Model (mascot)

- `data/mascots.ts`: `orb` (default Pulse Orb, Siri-style canvas waves) + wheel prizes `tv-bot` COMMON / `wave-cat` RARE / `rubber-hose` MYTHIC (original character, no licensed IP).
- Production finish: the orb draws contact shadow, breathing chromatic halo, a travelling-particle orbit ring, inner core luminosity and a specular crescent; `tv-bot` carries cabinet sheen, phosphor glow, scanline pattern, glass reflection, vents, side knobs and a standby LED; `wave-cat` has a second counter-rotating fur ring, inner ears, whiskers and glow face; `rubber-hose` gets a glass helmet dome with stars, rim rivets, reflection streaks, cell shading and blush dots. All keep `role="img"` aria labels and reduced-motion stills.
- Emotions HAPPY/SERIOUS/THINKING/ANGRY/SAD via `hooks/useMascotEmotion.ts` (deterministic: pending→THINKING, critical alert→ANGRY, risk→SERIOUS, nominal→HAPPY).
- TTS amplitude drives the orb/cat waves via `useSpeech` analyser (viseme fallback for Web Speech).
- Unlocks are **local per operator** (`user-store` `extras.mascotSkins`/`equippedMascot`/`seenMascots`). Backend `claim-wheel-spin` consumes the spin only — no mascot skin id is sent (backend catalog = suit skins). Pressing COLLECT applies the unlock, then closes the wheel modal automatically after a ~700 ms beat so the "skin added" state lands.

## Bonus cadence

One spin per **`WHEEL_CADENCE_DAYS` consecutive check-in days** (spec: `7`, weekly): a gap resets the run; earned milestones = Σ floor(run/N). Backend reads it from settings (`wheel_every_n()` in `backend/app/auth/service.py`); the frontend receives `wheelCadenceDays` via `GET /api/runtime-config` into `app-store` (non-persisted) so `earnedSpinsFor(checkIns, id, everyN)` / `useCheckIn().wheelEveryN` / `PrizeWheel` title stay in sync without a rebuild. `pending_spins` = milestones − `wheel_spins_claimed`. Set `WHEEL_CADENCE_DAYS=1` for testing (spin on the first check-in); at cadence ≠ 7 the "WEEKLY" copy degrades to "CHECK IN BONUS".

Wheel labels: segment text is tangential at r·0.74 in 8 px `var(--font-mono)` with 0.08 em tracking (the 10 px display font with 0.16 em tracking overflowed the ~49 px arc gap and printed labels on top of each other); bottom-half labels flip 180° so every word reads upright, and thin radial divider ticks separate the wedges.

## Vital Signs tiles (backend-mapped)

`lib/medbay-vitals.ts` defines the VITAL SIGNS strip; every tile reads zone `vitals` by key, so only metrics the backend body-status `linked_vitals` (or trends) actually reports get a tile. Mapping: **BMD** ← `bone_mineral_density_t_score` (spine + `bone_density` trend), **Sleep** ← `sleep_hours` (limbs + `sleep_hours` trend), **Temp** ← `core_temp_c` (head, exposed by the backend since it also drives the ≥39.5 °C head-critical rule + `core_temp` trend), **SpO2/HR/BP** ← `spo2_percent`/`heart_rate_bpm`/`systolic_bp_mmhg` (chest; BP parsed from `blood_pressure_mmhg` "sys/dia" + `systolic_bp` trend), **Glucose** ← `blood_sugar_mg_dl` (gut), **Radiation** ← `radiation_dose_msv` (skin + `radiation` trend), and in technical view **Acuity** ← `visual_acuity_logmar`, **Suit** ← `suit_pressure_kpa`, **CO2** ← `co2_partial_pressure_mmhg` (head; `suit_pressure`/`cabin_co2` trends). Every tile also carries a `metric` → `/api/v1/trends/{indicator}` mapping, so the per-vital graph view always has a real feed — "NO GRAPH FEED" is reserved for future vitals with no telemetry column. The shared `baseZones()` template (`data/crew.ts`) carries the same canonical keys so mock and REST render identical tiles; the spec's "Height & weight" slot was retired — the backend has no anthropometric feed and nothing is fabricated.

## Demo health arc (mock provider only)

`data/sim-progress.json` + `services/sim-progress.ts`: keyframed zone vitals/statuses and telemetry targets, interpolated every `tickMs` (5 s), looping. `MockHealthDataProvider` applies it in `getCrew`/`getCrewMember`/`getTelemetrySeries`; `useBodyStatus` silently re-polls on `SIM_TICK_MS` only when `provider.kind === "mock"` — REST/backend behaviour is untouched. Vital statuses derive from the same thresholds as the deterministic triage engine (`evaluateLocally` mirror); the vitals strip shows `SIM FEED` instead of `LIVE FEED` under mock so the demo arc is never presented as real telemetry.

Under the REST provider the same dataset powers an on-demand **scenario player**: the VITAL SIGNS header carries a `▶ RUN SIM` / `■ STOP · N INS` button (`useBodyStatus.toggleSim`). Each `tickMs` it samples `simIngestPayload` (frontend metric → ingest field map; non-ingestable hints like exertion/fatigue are skipped, nothing fabricated) and POSTs a real `TelemetryIngestRequest` to `/api/v1/telemetry/ingest` — an actual DB row per tick — then silently refreshes body-status and dispatches `SIM_TICK_EVENT`, which every `useTelemetry` hook listens to so trend graphs grow point-by-point. The counter shows live insert count; while running the feed reads `SIM FEED`. The button only renders for `provider.kind === "rest"` (mock already self-drives the arc).
