# Tempus Pro Asynchronous Telemedicine Sync Queue (`doc/back/telemedicine/sync-queue.md`)

## Overview

Feature 4.2 implements an asynchronous store-and-forward telemedicine pipeline modeled after military/aerospace "Tempus Pro" vital signs monitors:
1. **Store-and-Forward Buffering:** Tier-3 clinical alerts and critical anomalies generated by triage and telemetry ingestion are captured in `TelemedicineAlertRecord` tables with `transmission_status = "pending"`.
2. **Deep-Space Communication Awareness:** Deep-space missions (Mars, Lunar Farside, Transit) experience comm delays up to 20+ minutes (`earth_comm_latency_sec`). When `LocationContextRecord.offline_fallback_active` is True, real-time communications are marked buffered (`comm_window_open = False`).
3. **Multi-Modal Diagnostic Bundling:** When inspecting the queue, each alert is packaged into a `TempusProPacketSchema` enriched with:
   - Latest multi-modal Artemis Standard Measures vitals (`TelemetryRecord`).
   - Polynomial Ridge regression trend forecasts for `heart_rate_bpm` and `spo2_percent` (with cold-start safety).
4. **Batch Transmission ("Flush"):** When ground communication windows open or emergency override is triggered, pending alerts are bulk-transmitted and marked `"transmitted"` with UTC timestamps.

## API Contracts

### 1. `GET /api/v1/telemedicine/sync-queue`
- **Query Params:**
  - `astronaut_id: Optional[str] = None`
  - `transmission_status: Optional[str] = None` (`"pending"` or `"transmitted"`)
- **Response:** `TelemedicineSyncQueueResponse`
  - Operational metadata: `location_setting`, `earth_comm_latency_sec`, `offline_fallback_active`, `comm_window_open`.
  - Queue telemetry: `pending_count`, `transmitted_count`.
  - Packets: List of `TempusProPacketSchema` containing raw triage findings, telemetry snapshot, and Ridge forecasting summaries.

### 2. `POST /api/v1/telemedicine/flush`
- **Payload:** `TelemedicineFlushRequest`
  - `astronaut_id: Optional[str] = None`
  - `packet_ids: Optional[list[int]] = None`
  - `force_flush: bool = True`
  - `ground_station: str = "NASA-JSC-MCC-Houston"`
- **Behavior:**
  - Evaluates active comm window. If `offline_fallback_active == True` and `force_flush == False`, returns HTTP 400 detailing lockout.
  - Transitions matching pending alert records to `transmission_status = "transmitted"` and sets `transmitted_at = datetime.now(timezone.utc)`.
  - Commits updates to database and returns `TelemedicineFlushResponse` with `flushed_count`, `remaining_pending_count`, and the flushed packet list.
